# Contributing to Kairosplit

First off, thank you for considering contributing to Kairosplit! This is a community-driven specification project, and we need your help to build a solid foundation.

## How to Contribute

### 1. Architectural & Concept Discussions
Since we are starting from scratch, the best way to contribute right now is to participate in our [Discussions](../../discussions) and comment on open [Issues](../../issues). Let's freeze the core concept before writing code!

### 2. Creating Implementation Issues
If you have a concrete idea for a feature (an anomaly, a specific era, or a tool):
* Open a new Issue describing the feature.
* Discuss its technical viability with the community.
* Once approved, it can be assigned to you.

### 3. Code & Pull Requests (Future Phase)
When we start writing code, please follow these guidelines:
* **Branching:** Create a separate branch for each feature or fix (e.g., `feature/entropy-engine` or `fix/issue-42`).
* **Code Style:** We aim for highly modular and decoupled code to prevent core mechanics from breaking when adding new eras.
* **Testing:** All core mechanics (like entropy calculations or chunk processing) must include tests.

Let's build a dynamic multiverse together!
